# Надёжность и поведение кешей

Гейтвей устроен так, чтобы устаревшее состояние не переживало ключ или
конфигурацию, к которым относится.

## Идентификаторы запросов

Каждый ответ несёт `X-Request-Id`. Присланное клиентом значение сохраняется,
если это не более 64 символов `A-Z a-z 0-9 . _ -`; иначе генерируется новый
`req_…`. Идентификатор попадает в тело каждой ошибки как `request_id`, в
структурный лог рядом с ошибками провайдера и в CORS-заголовки, чтобы его мог
прочитать браузерный клиент. Указывай его в отчёте о проблеме.

## Что кешируется и на сколько

| Слой | Область | Время жизни | Инвалидация |
|---|---|---|---|
| Clerk-сессионный JWT | хеш одного ключа | до истечения токена (около минуты) | истечение, замена ключа, sweep при `Reload` |
| Пул attestation-токенов | один субъект | до истечения (около четырёх минут, одноразовые) | использование, повтор на `403`, замена ключа, sweep |
| Результаты каталога (панель) | провайдер + метка + фильтр | 10 минут | **bypass cache**, добавление/удаление/перехват ключа, рестарт |
| Кулдауны | метка ключа или пул без метки | заголовок сброса провайдера | **Resume**, замена или удаление ключа, истечение |
| HTTP/2-соединение | клиент | процесс | рестарт процесса |

Фоновый sweep раз в несколько секунд при работе `up` или `gui` убирает
просроченные токены, пустые пулы и просроченные attestation-токены.

Замена ключа для существующей метки (`account add`, **Save credential** в панели,
перехват) снимает кулдаун метки, сбрасывает её сессии и кеш каталога
провайдера. Удаление ключа делает то же. Горячая перезагрузка также чистит
просроченное состояние.

CLI `models discover` всегда без кеша; кеш каталога использует только панель, и
её флажок принудительно перезапрашивает.

## Повторы и таймауты

| Ситуация | Поведение |
|---|---|
| Транспортная ошибка до первого байта | один повтор |
| `5xx` до начала стрима | один повтор |
| Стрим умер до первого события | один повтор |
| `403` по attestation | один повтор со свежим токеном, затем `cloudflare_challenge` |
| Битый блок инструментов | один ремонтный ход, только если ничего не ушло |
| Пустой ответ (200 или только `processing`) | один повтор, только если ничего не ушло |
| `429` | без повтора; метка остывает до сброса |
| `402 insufficientBalance` | без повтора и кулдауна; отдаётся `insufficient_balance` |
| Промпт длиннее контекста | отклоняется до отправки, если у алиаса есть `max_context` |
| Слишком много вложений | отклоняется до загрузки, если у алиаса есть `max_images` |
| Молчащий стрим | обрывается через окно неактивности алиаса (по умолчанию 2 мин), ответ `upstream_timeout` |
| Тело запроса | лимит 8 МиБ, 90 с до заголовков, 10 мин на вызов |

Повтор возможен только пока клиент ничего не увидел, поэтому в стриме текст не
дублируется.

## Ошибки

У ошибок один формат на протокол: `{"error":{"message","type","code","request_id"}}`
для OpenAI-эндпоинтов, `{"type":"error","error":{…}}` для Anthropic. Коды
стабильны и описаны в [venice-web.md](venice-web.md#failure-codes): клиент может
ветвиться по `code`, а не по тексту. К `429` прилагается `Retry-After`.

## CORS

Preflight `OPTIONS` отвечает `204` без ключа, ответы разрешают `Authorization`,
`X-Api-Key` и заголовки протокола. Куки не используются, поэтому
`Access-Control-Allow-Origin: *` безопасен. Браузерная страница может вызывать
loopback-гейтвей напрямую.

## Метрики

`GET /metrics` отдаёт текст Prometheus без ключа: `allaiis_requests_total` по
алиасу, протоколу и статусу, суммы длительности и символов, гейдж обслуженных
моделей и `allaiis_up`. Парсер инструментов добавляет
`allaiis_tool_unwrap_total`, `allaiis_tool_name_fold_total`,
`allaiis_tool_name_suffix_total` и `allaiis_tool_unknown_total`, поэтому
переформирование видно без лога; растущий счётчик незнакомых имён значит, что
модель называет инструменты вне каталога. Четыре счётчика и набор имён
переживают рестарт: они лежат в `tool-names.json` в каталоге данных, пишутся не
чаще раза в три секунды через временный файл и читаются при старте, так что
предупреждение врача не стирается перезапуском. Кнопка **Reset** на карточке
Tool reshaping (или `POST /api/tools/reset`, или `allaiis tools reset`) обнуляет
и то и другое и удаляет файл; `allaiis tools reset --expired` убирает только
просроченные имена и сохраняет свежие улики; `allaiis tools show` печатает запись со временем
последнего появления каждого имени и помечает просроченные как expired, чтобы
остановленный гейтвей не делал вывод лживым — так починенный список инструментов перестаёт
нести старую вину. Имя также истекает через `tool_name_ttl_days` (по умолчанию
30, `0` хранит имена вечно), чтобы исправленный месяцы назад алиас не держал
предупреждение живым; итоговые счётчики накопительные и остаются. Кардинальность следует за настроенными алиасами.
Собирай его loopback-коллектором.

## Мягкая остановка

`SIGINT`/`SIGTERM` прекращают приём соединений и дают запросам в полёте десять
секунд до закрытия слушателя.

# Запуск у себя

Это схема на одной машине: шлюз стартует вместе с сеансом, пишет ротируемый лог,
и его можно сохранить. Рассчитано на личный компьютер, не на ферму серверов.

## Перед первым запуском

```powershell
.\allaiis.exe init
.\allaiis.exe web chrome
# войдите во вкладке, затем перехватите сессию:
.\allaiis.exe web login --label personal
```

Задайте парольную фразу для текущей оболочки, чтобы фоновая задача стартовала
без запроса:

```powershell
$env:ALLAIIS_VAULT_PASSPHRASE = "длинная парольная фраза"
```

Эту же фразу использует `service install`; она попадает в пусковой скрипт,
поэтому хранилище защищено правами на файлы — и они у него есть.
Пусковой скрипт и файл `service.cmd` имеют права `0600` и хранят парольную фразу
открытым текстом; не держите каталог данных на общих путях.

## Старт при входе

```powershell
.\allaiis.exe service install
.\allaiis.exe service status
.\allaiis.exe service remove
```

В Windows это файл `service.cmd` в каталоге данных и ярлык в пользовательской
папке «Автозагрузка» — без прав администратора, поэтому не планировщик задач. В
Linux и macOS пишется unit-файл и печатаются две оставшиеся команды root
(`systemctl enable --now …`, `launchctl load …`).

## Логи

`service.cmd` запускает `gui --no-open --ui 127.0.0.1:8431 --log-file <данные>/logs/gateway.log --log-max-mb 32
--log-keep 5`. Файл ротируется на 32 МиБ, пять старых остаются. Те же флаги
работают при ручном запуске:

```powershell
.\allaiis.exe up --log-file .\logs\gateway.log
```

## Сохранение и восстановление

```powershell
.\allaiis.exe backup D:\allaiis-backup
.\allaiis.exe backup restore D:\allaiis-backup --force
```

Хранилище и так зашифровано; в копию добавляется манифест с SHA-256 по каждому
файлу, и `restore` отказывается принимать файл, чей хэш изменился. Перед
восстановлением остановите шлюз.

## Обновление

```powershell
.llaiis.exe update --check    # какой последний тег
.llaiis.exe update            # скачать, сверить хэш, подменить
```

`update` берёт сборку под эту ОС и архитектуру из свежего релиза на GitHub,
сверяет её с `SHA256SUMS` релиза, переименовывает работающий файл в `.old` и
ставит новый. Приватному репозиторию нужен `GITHUB_TOKEN` в окружении. После
обновления перезапустите шлюз; скрипт службы сделает это сам за пять секунд.

Без релиза или для локальных правок пересоберите вручную:

```powershell
.llaiis.exe service remove
go build -o allaiis.exe ./core/cmd/allaiis
.llaiis.exe doctor
.llaiis.exe service install
```

Ни один путь не трогает хранилище и конфиг. `doctor` запускается до того, как
новый файл снова попадёт в автозагрузку.

## Когда что-то сломалось

- `allaiis doctor` — локальные проверки, без квоты провайдера; запаркованные метки и срок перечисляются, так что `429` из пула объяснён; Строка `web plan` печатает по каждой сохранённой сессии остаток чатов, план и
баланс кредитов, так что `402` читается без догадок: платным моделям нужны
кредиты, бесплатным нет. e2ee-алиасы проверяются attestation живьём, это не
тратит квоту, а гостевая сессия на таком алиасе отмечается — она не может запускать e2ee; `--offline` пропускает эту единственную сетевую проверку.
- `allaiis web quota` — остаток счётчиков сессии и время сброса.
- `allaiis web e2ee --model <e2ee-модель>` — проверяет attestation анклава для всех сохранённых сессий (или одной с `--label`), печатает пройденные проверки и шлёт один запечатанный канареечный ход.
- панель на `http://127.0.0.1:8431/` — квоты, пробы, логи, алиасы.
- `allaiis smoke --json` — полный обход через временный гейтвей; у каждого результата есть `code`, так что запаркованная модель (`insufficient_balance`) отличима от настоящей поломки; `--allow <code>` (можно повторять) считает ожидаемый код, например намеренно битый алиас, и не валит прогон.

`403` с `cloudflare_challenge` значит, что attestation протухла: запустите
`allaiis web chrome` и снова `web login` для этой метки.

## Перевод клиента на наш API

```powershell
.\allaiis.exe service status     # гейтвей должен быть уже поднят
.\allaiis.exe doctor             # без ошибок, нужный алиас в списке
.\allaiis.exe export opencode
```

Команда печатает блок провайдера для конфига OpenCode с локальным ключом. Гейтвей
отдаёт формы OpenAI, Responses и Anthropic Messages на одном порту, поэтому любому
клиенту, который говорит на одной из них, нужны только базовый URL
`http://127.0.0.1:8420/v1` и ключ из `allaiis key`.

Выбирайте алиас, который отвечает: бесплатные модели работают и с исчерпанным
планом, а платный или `e2ee`-алиас отдаёт `402`, пока у метки нет баланса.
`e2ee`-алиасу к тому же нужна вошедшая метка, он тратит круг attestation, а
вскрытие его ответа пока не проверено — начинайте с бесплатного алиаса и
переходите, когда первая канарейка `allaiis web e2ee` расшифруется.
